# Retained experiment artifacts

`egobody_v20/` and the three `egohuman_external_*.tex` files are copied from
the prior draft as source-generated evidence. They are retained for provenance
and later table generation, not as editable manuscript prose.

`egobody_v20/paired_recording_statistics.tex` is generated from the retained
frozen-Test `recording_metrics.csv` by
`Movie3R/versions/v20/egobody/paired_recording_statistics.py`. It reports a
retrospective paired analysis over the 43 recording macros and does not read
RGB, GT, or any newly generated prediction.

`final_training_curve/` contains the recovered optimization history of the
reported final Shot3R checkpoint. The source log is
`Movie3R/checkpoints/v9_mixed_60h_pose_human_lora_bs10/train.log`; its SHA-256,
the recovery precision, dataset order, and checkpoint identity are recorded in
`final_training_curve/recovery_summary.json`. The CSV files retain the parsed
training, validation, and test values used to generate the PDF/SVG/PNG figure.

`egohumans_v19/paired_capture_statistics.tex` is generated from the retained
29 capture reports and their frozen Test summary by
`Movie3R/versions/v19/egohumans/paired_capture_statistics.py`. It preserves
the 90-case point estimates while clustering uncertainty and the sign-flip
test at the 27-capture level.

`egohumans_state_isolation/` contains the anonymous summary and compact table
for the same-checkpoint recurrent-state control on EgoHumans formal90. The
original Human3R checkpoint processes identical post-cut frames either with
the preceding-shot state or from its initial state. The gauge-invariant
within-shot camera drift is aggregated over 90 cases and 27 capture macros;
the complete caches, runtime bindings, and file hashes remain outside the
Overleaf package in the version-specific private audit directory.

`josh_egohumans90/`, `josh_egobody129/`, and `josh_harmony4d88/` retain the
publication-facing output of the official JOSH full-video runs on all three
primary protocols. Each directory contains the complete-denominator summary,
per-case table, native-output support, independent paper-export audit, and a
human-readable report. The numerical JSON/CSV files are copied without
editing from the audited experiment outputs; raw RGB, licensed weights, and
large native prediction directories remain outside the paper package.

`runtime_memory/` contains the rendered runtime table and the sealed JSON/MD
report from which its values were exported. The report records every timed
repetition, the timing scope, hardware and software versions, checkpoint and
manifest hashes, and the benchmark-script hash. The historical report uses
the former Bridge3R name for the same model now presented as Shot3R; its raw
contents are retained unchanged.

`runtime_h4d150/` contains the anonymous publication-facing evidence for the
seven-method full-system runtime study: the frozen five-case selection, timing
protocol, aggregate CSV, and rendered LaTeX table. The complete per-case JSON
records and hashes remain in the private version audit directory because they
contain local machine paths; none are required to compile or verify the
reported aggregate values.

`harmony4d_boundary_association_table.tex` is a presentation table generated
from the formal $N=88$ evaluator-only direct-association audit. Its source
summary and exact frozen runtime-manifest hash are retained in the version
root under `evidence/harmony4d_boundary_association/`. It is supplementary
single-dataset component evidence, not a cross-dataset association claim.

harmony4d_lambda_sensitivity.tex is generated by
Movie3R/versions/v17/harmony4d/render_v017_lambda_sensitivity_tables.py
from the frozen train-only Harmony4D sensitivity summary. It reports the full
pre-registered blend grid as means and medians over the evaluator-complete
development cases; it is descriptive only and does not reselect the fixed
publication value $\lambda=0.5$. The lock, manifest ledgers, candidate list,
per-sequence reports, and source summary are retained outside the Overleaf
source under evidence/harmony4d_lambda_sensitivity/.
